
MultiHopper API Integration Details
SolSend implements the complete Build & Route pattern required for the MultiHopper Superteam Challenge, utilizing 3-hop transaction dispersion to guarantee payout privacy.

Core Protocol Flow (lib/multihopper.ts)
The execution engine coordinates 5 distinct stages with the MultiHopper API:

Transfer Initialization (POST /transfers)

Submits recipient destination addresses, amounts (in base lamports/units), token mint (SOL native mint or USDC SPL mint), hops: 3, and arrivalSeconds: 600.
Preparation (POST /transfers/:id/prepare)

Retrieves the un-signed keeperFundingTx payload generated by MultiHopper.
Client-Side Signing

Prompts the user's connected wallet (Phantom, Solflare, or Backpack) to sign the keeperFundingTx along with secondary setup transactions (routeInitTxs, orchestratorInitTx, sessionInitTxs, dispersionInitTxs).
Confirmation & Broadcast (POST /transfers/:id/confirm-broadcast)

Submits signed transaction wire data back to MultiHopper for server-side keeper execution and route orchestration.
Asynchronous Polling (GET /transfers/:id)

Polls the transfer status every 3 seconds until a terminal state is reached (completed, failed, expired, or refunded) with an 8-minute maximum timeout.
Revenue Share & Fee Structure
Revenue Share: SolSend automatically attaches the registered fee header/API key to all routed transactions, ensuring 0.25% revenue share generation.
Network Fees: Dynamically calculated prior to execution to warn users of insufficient SOL for transaction signatures or ATA (Associated Token Account) rent creation.
Batching Limits
Maximum of 20 recipients per MultiHopper route session to guarantee transaction size compliance under Solana's 1232-byte packet limit.
